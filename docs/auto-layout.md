# 自動排版

自動排版只有一個按鈕、沒有選項：同一套規則套用在每一張圖，依圖的結構決定排法。只有在控制時間的地方看圖的大小：超過 16 個狀態只用一種間距，線很多（超過 64 條，見第 4 步）的圖只收尾一部分候選。程式在 `packages/core/src/tidy.ts`（產生與修整候選排法）和 `packages/core/src/layout-score.ts`（評分）。

## 流程

1. **分析**：互不相連的子圖（島）各自排好再並排，重設狀態那一塊在最前面。每個子圖找出重設狀態、迴圈，以及三個互相連接的狀態（三角形）。
2. **候選排法**，每種都在兩種間距下各排一次（一般間距，以及留給最長標籤的寬間距；寬間距最多留 320px，更長的標籤會擠到；標籤夠短時兩種間距一樣，只排一次；超過 16 個狀態只用寬間距）：
   - **方格**：長寬接近（或略寬）的方格，重設狀態在最左欄，用模擬退火交換格子，減少交叉、穿過狀態的線、斜線和長線。每一步只重算移動到的狀態的線，所以能試很多步；除了移動單一狀態，也會整排或整欄對調、左右或上下翻轉。每種起始排法退火後再逐一試過所有單步和整排整欄的移動，直到沒有更好的為止（一輪要試的步數超過退火的四倍時，也就是狀態多、線又密的大圖，每個狀態只試附近幾排幾欄的格子，範圍以四次退火的工作量為限）；12 個狀態以內多試一種更寬的方格（這個上限也讓 cle_locked 保持使用者選的環形，見 p08、p09；目前評分其實偏好 5、6 欄的方格），16 個狀態以內把第二好的方格也交給評分挑選。位置完全相同的排法只畫、只評分一次。重設狀態在左上角時，沿對角線翻轉（列換成欄）的方格成本相同，取從重設狀態出去的線比較往右的那一個，讓迴圈從左上順時針走。
   - **分層**：由左到右或由上到下（Sugiyama 式），回頭的線不打亂主流程。
   - **蛇形**：把很長的分層流程折成幾排，一排往右、下一排往左。
   - **環形**：最大的「拿掉任何一個狀態都還連在一起」的區塊繞成長方形，重設狀態在左上、順時針走。掛在旁邊的短迴圈各自排成小三角形、正方形或長方形，貼在出發的狀態旁、朝外。
   - **中心**：和其他每個狀態都相連的狀態（輪軸）。其他狀態自己繞成一圈時，輪軸放在中間、其他狀態繞著它排在周圍八格上（先用上下左右；周圍剛好四個時，也試排在四個斜角，成正方形）；四個狀態兩兩相連時，排成正三角形、第四個在正中央，重設狀態若在角上，一定放左上角（三角形尖端朝下，流程沿著水平的上邊往右走；或尖端朝右），不會尖端朝上或朝左、把重設狀態放到下方或中間——顯示標籤時，只因多一個標籤碰到線，分數曾把 k4 和 vending 整個翻過來。輪軸是重設狀態時，另外試扇形：輪軸在左邊，其他狀態在它的上、右、下。這些形狀照原樣評分，不再做局部形狀調整；換一個輪軸只是狀態名字不同、畫出來完全一樣的（例如四個狀態兩兩相連），只排一次。
   - **輪狀**：不必和每個狀態都相連，只要連到 5 個以上、而且至少是其他狀態的一半（最多 40 個狀態），就把它放在中間，和它相連的狀態照它們自己那條鏈的順序繞在外圈，像鐘面一樣讀：外圈排在長方形格子的邊上（`hub-box-欄x列`，取輻線都不被擋住的三種最好的大小）或略寬的橢圓上（`hub-oval`；中心和鄰居之間有來回兩條線時改用正圓 `hub-ring`、輻線等角，因為一條輻線上有兩條線，輻線之間要更多空間）。沒有直接連到中心的狀態（例如分派器每條鏈中間的狀態）放在外圈之外、靠著自己的鄰居。中心是重設狀態時，起始箭頭從左邊進來，那個方向不放狀態。「每一步都能中止回到 IDLE」「每個狀態都能進 ERROR」「IDLE 分派到好幾條鏈」這類狀態機，以前排成方格時，回中心的線會擠成一束、幾乎重疊；輪狀排法讓每條線各走各的方向。這些形狀也照原樣評分，不做局部形狀調整、不微調（外圈的狀態往中心移，會擋住後面的輻線）。
3. **局部形狀**：有兩個狀態互指的三角形排成正三角形（環形裡只左右滑動，每排保持水平），兩個共用一邊的三角形拼成菱形。其他三角形也會試著不調整，看哪個分數好。
4. **收尾**：線超過 64 條的密圖，先把每個候選的線都當直線，數交叉和穿過狀態的次數，只收尾最少的 8 個（密圖的弧線解不開多少交叉，直線的數字就排得出先後；全部收尾要好幾秒）。對齊 20px 格線；會穿過狀態的線改成弧線，來回兩條線平行錯開；和別條線交叉的線，若彎成弧能避開所有狀態又減少交叉，就彎過去（交叉最多的線先處理，最多幾輪；起始箭頭也算一條線，弧線會繞過它，不會穿過）；自迴圈朝最空的一側、避開附近的線（來回兩條平行線比中線寬），也不壓在起始箭頭上，起始箭頭從空的一側進來（不只避開狀態，也不和任何線交叉或沿著線走；左邊被線擋住時，先試著讓線繞開，繞不開才換一側）。
5. **評分**：見下一節。
6. **修正**：還有交叉、重疊或穿過狀態的線，而且這些扣分拿掉後可能領先的候選（最多五個，密圖兩個），試著把間距拉開 1.25 或 1.5 倍。拉開是有代價的：1.5 倍的圖面積是 2.25 倍，在螢幕上狀態只剩三分之二大。真的需要空間的（拉開後穿過狀態的線、重疊的標籤或太近的狀態，比目前保留的那一張少），用拉開後的格距評分，空間不算錢；只是為了解開交叉而再拉大的，用目前保留的那一張的格距評分，也就是照它實際上比較大、線比較長來算，要贏得靠真的比較乾淨（以前拉開不用錢，12 個狀態的 gen12_5 為了一樣多的交叉排成 1359×1446px，現在是 759×1026px）。拉開後的排法問題比較少、分數也比原來好才保留。修不掉的問題會回報，編輯器顯示在畫面下方。
7. **微調**：最好的兩個裡（分數和最好的差不到一半的才算：微調是修圖，不是另畫一張），有太長箭頭的狀態會試著移到離鄰居最近的三個空格，取分數最好的那個。不會把重設狀態移到別的狀態右邊。另外先微調像修正那樣「還有交叉、重疊或穿過狀態的線，但扣分拿掉後可能領先」的最好兩個：移動一個狀態可能解開拉開間距解不開的交叉（例如 cle_locked 顯示標籤時）。所有微調共用一個嘗試次數上限：min(48, 40000 ÷ 線數²)，線越多試得越少，超過約 280 條線就不微調。最後，為拉開付了代價、因此排不進前兩名的排法裡最好的一個也微調（最多 6 次嘗試）：移一個狀態把長線收回來，它可能就領先了。修正和微調都不會加入和既有候選位置完全相同的排法。

每個候選都從頭收尾：之前排版（或使用者）留下的弧線、自迴圈方向和起始箭頭方向都先清掉，起始箭頭預設從左邊進來，被擋住才換邊；輸出的方向就是評分時檢查過的方向。重設狀態上方的狀態比下方多的排法（例如退火停在重設狀態在最左欄底部的方格，像 e2e 檢查的 gen14_4；或三角形從重設狀態那一排往上尖）也上下翻轉收尾一次，兩個都評分：翻過來的沒有比較多交叉、穿過狀態的線、重疊的標籤或太近的狀態，分數也沒有差超過 25，就用翻過來的，讓重設狀態在上、流程從上面開始。翻過來不是同一張圖（往回的線在一排下方彎、往前跳的在上方彎，弧線方向不同），所以要比：例如 gen17_7 的方格拉開後，翻過來多三個交叉，就保持原樣。翻過的候選在修正時照原來的方向拉開再比一次；微調時每一步照候選目前的方向試，微調完重設狀態被移到下面的，才比一次翻不翻。重設狀態在中間那一排（左邊開始的菱形或扇形，使用者選的 p01、p11、p20）不翻。中心排法照原樣，不翻（它們自己決定重設狀態的位置，翻過來只會和另一個輪軸的形狀重複）。

## 評分

分數越低越好，是各項計數乘上權重的總和（`WEIGHTS`，在 `layout-score.ts`）。分數相同時，從重設狀態出去的線（依檔案中的順序）越往右的排法優先，所以迴圈會從左上順時針走、第一個狀態接在重設狀態右邊。

| 項目 | 意思 |
| --- | --- |
| `crossings` | 線與線交叉（起始箭頭也算一條線：被線切過，或有線貼著它走，都算） |
| `throughStates` | 線穿過不相關的狀態 |
| `labelOverlaps` | 標籤互相重疊或蓋到狀態 |
| `tooClose` | 兩個狀態太近 |
| `uneven` | 有兩個狀態互指的三角形不是正三角形（正三角形正中央的輪軸和角落連成的三個小三角形不算；但輪軸若還連到三角形外的狀態，例如五個狀態兩兩相連排成格子時，照算） |
| `floating` | 和其他狀態都不在同一排或同一欄的狀態（輪狀的中心狀態夾在兩個鄰居正中間時不算） |
| `long` | 比最短的線長 1.5 倍以上的線，超出多少（以最短的線為單位；格距比最短的線短時用格距，至少一格 20px）。有 9 個以上鄰居的狀態，它的線要超過容得下這些鄰居的那一圈才算長；輪狀中心的線若得彎過別的狀態，每條多算一格 |
| `leftOfStart` | 在重設狀態左邊的狀態（閱讀應從左邊的重設狀態開始）。重設狀態本身是中心（超過 5 個鄰居，上、下、右都有狀態）時不算：它在中間才讀得懂 |
| `aspect` | 形狀偏離寬高比 1.6（略寬於高，像螢幕）多少 |
| `labelOnEdges` | 標籤壓在其他線上（線的每一段都檢查，不只取樣點） |
| `backward` | 逆著主流程（左到右或上到下）的線 |
| `asymmetry` | 不對稱的程度 |
| `slanted` | 斜線 |
| `length` | 線的總長 |
| `area` | 面積 |

## 用「選一個」調整權重

權重不是憑感覺定的：把同一台狀態機的兩種排法並排給人看，請他選比較好的，再調整權重讓分數和他的選擇一致。目前的權重和 23 組選擇全部一致。

這些選擇存在 `packages/core/test/layout/fixtures/preferences.json`。`tidy.test.ts` 裡有一個測試會逐組檢查「被選中的排法分數比較低」，所以以後改評分時，只要和任何一組選擇衝突，測試就會失敗。

再做一輪：

1. 產生比較頁：
   ```sh
   pnpm taste-test                       # 或 node tools/layout-taste-test/make-pairs.ts <輸出資料夾>
   ```
   會在 `tools/layout-taste-test/out/` 產生 `index.html`（比較頁）和 `pairs.json`（每組的兩種排法）。要比較的狀態機在 `tools/layout-taste-test/machines.ts`，可以自行加入。
2. 用瀏覽器開啟 `index.html`，每組選 A、B 或「差不多」，最後按「複製選擇（JSON）」，存成 `picks.json`。
3. 把選擇加進測試資料，並看目前的分數和幾組一致：
   ```sh
   node tools/layout-taste-test/apply-picks.ts tools/layout-taste-test/out/pairs.json picks.json 2026-11-01
   ```
4. 若有不一致的組，調整 `layout-score.ts` 的權重或加新的評分項目，直到 `pnpm test` 全部通過。

## 量測排版品質

改排版規則之前和之後，用同一把尺量 84 台形狀各異的狀態機（Verilog 測試檔、手畫的例子、常見的控制器如 CPU、UART、I2C、SPI、AXI、電梯、紅綠燈、每一步都能中止的流程、錯誤匯集、分派器、序列偵測器，還有環、鏈、樹、星形、網格和亂數產生的圖），在 `tools/layout-bench/`：

```sh
pnpm layout-bench --out tools/layout-bench/out-new --svg                     # 排版並量測，約 30 秒；--filter '<regex>' 只跑幾台（等同 node tools/layout-bench/run.ts）
node tools/layout-bench/run.ts --out tools/layout-bench/out-old --core ../另一份原始碼/packages/core   # 用另一份程式碼（例如 main）排版，同一把尺量
node tools/layout-bench/compare.ts tools/layout-bench/out-old tools/layout-bench/out-new --html compare.html   # 逐台比較，並產生前後對照頁
```

量的不是排版自己的分數，而是從畫出來的圖直接數（`metrics.ts`）：交叉、穿過狀態的線、重疊的標籤、太近的狀態，以及分數看不到的「亂」——從同一個狀態出去、夾角不到 15 度的線（看起來像一條粗線）、彎度 100px 以上的大弧線、擦過不相關狀態的線，還有圖的大小。數字看不到全部，改完一定要看對照頁的圖。`machines.ts` 可以自行加入狀態機。

`layoutCandidates(d)`（`@fsm/core`）會回傳某張圖所有收尾過的排法、各自的分數和評分用的格距（`step`，交給 `layoutScore(d, plan, step)` 會得到同一個分數），可以用來檢查或做自己的比較。由幾個島組成的圖只回傳並排後的結果。

排版的選項 `margin`（預設 60）不是圖到邊的距離：圖的外框從 `margin - 20`（至少 20）對齊格線的位置開始，所以邊上實際留約 40px。
