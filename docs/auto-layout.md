# 自動排版

自動排版只有一個按鈕、沒有選項：同一套規則套用在每一張圖，依圖的結構決定排法，不依狀態數量切換。程式在 `packages/core/src/tidy.ts`（產生與修整候選排法）和 `packages/core/src/layout-score.ts`（評分）。

## 流程

1. **分析**：互不相連的子圖（島）各自排好再並排，重設狀態那一塊在最前面。每個子圖找出重設狀態、迴圈，以及三個互相連接的狀態（三角形）。
2. **候選排法**，每種都在兩種間距下各排一次（一般間距，以及留給最長標籤的寬間距）：
   - **方格**：長寬接近（或略寬）的方格，重設狀態在最左欄，用模擬退火交換格子，減少交叉、穿過狀態的線、斜線和長線。每一步只重算移動到的狀態的線，所以能試很多步；除了移動單一狀態，也會整排或整欄對調、左右或上下翻轉。每種起始排法退火後再逐一試過所有單步和整排整欄的移動，直到沒有更好的為止；12 個狀態以內多試一種更寬的方格（這個上限也讓 cle_locked 保持使用者選的環形，見 p08、p09；目前評分其實偏好 5、6 欄的方格），16 個狀態以內把第二好的方格也交給評分挑選。位置完全相同的排法只畫、只評分一次。重設狀態在左上角時，沿對角線翻轉（列換成欄）的方格成本相同，取從重設狀態出去的線比較往右的那一個，讓迴圈從左上順時針走。
   - **分層**：由左到右或由上到下（Sugiyama 式），回頭的線不打亂主流程。
   - **蛇形**：把很長的分層流程折成幾排，一排往右、下一排往左。
   - **環形**：最大的「拿掉任何一個狀態都還連在一起」的區塊繞成長方形，重設狀態在左上、順時針走。掛在旁邊的短迴圈各自排成小三角形、正方形或長方形，貼在出發的狀態旁、朝外。
   - **中心**：和其他每個狀態都相連的狀態（輪軸）。其他狀態自己繞成一圈時，輪軸放在中間、其他狀態繞著它排在周圍八格上（先用上下左右）；四個狀態兩兩相連時，排成正三角形、第四個在正中央。輪軸是重設狀態時，另外試扇形：輪軸在左邊，其他狀態在它的上、右、下。這些形狀照原樣評分，不再做局部形狀調整；換一個輪軸只是狀態名字不同、畫出來完全一樣的（例如四個狀態兩兩相連），只排一次。
3. **局部形狀**：有兩個狀態互指的三角形排成正三角形（環形裡只左右滑動，每排保持水平），兩個共用一邊的三角形拼成菱形。其他三角形也會試著不調整，看哪個分數好。
4. **收尾**：對齊 20px 格線；會穿過狀態的線改成弧線，來回兩條線平行錯開；和別條線交叉的線，若彎成弧能避開所有狀態又減少交叉，就彎過去（交叉最多的線先處理，最多幾輪；起始箭頭也算一條線，弧線會繞過它，不會穿過）；自迴圈朝最空的一側、避開附近的線（來回兩條平行線比中線寬），也不壓在起始箭頭上，起始箭頭從空的一側進來（不只避開狀態，也不和任何線交叉或沿著線走；左邊被線擋住時，先試著讓線繞開，繞不開才換一側）。
5. **評分**：見下一節。
6. **修正**：還有交叉、重疊或穿過狀態的線，而且這些扣分拿掉後可能領先的候選（最多五個），試著把間距拉開 1.25 或 1.5 倍。修不掉的問題會回報，編輯器顯示在畫面下方。
7. **微調**：最好的兩個裡（分數和最好的差不到一半的才算：微調是修圖，不是另畫一張），有太長箭頭的狀態會試著移到離鄰居最近的三個空格，取分數最好的那個（嘗試次數有上限，大圖也很快）。不會把重設狀態移到別的狀態右邊。

## 評分

分數越低越好，是各項計數乘上權重的總和（`WEIGHTS`，在 `layout-score.ts`）。分數相同時，從重設狀態出去的線（依檔案中的順序）越往右的排法優先，所以迴圈會從左上順時針走、第一個狀態接在重設狀態右邊。

| 項目 | 意思 |
| --- | --- |
| `crossings` | 線與線交叉（起始箭頭也算一條線） |
| `throughStates` | 線穿過不相關的狀態 |
| `labelOverlaps` | 標籤互相重疊或蓋到狀態 |
| `tooClose` | 兩個狀態太近 |
| `uneven` | 有兩個狀態互指的三角形不是正三角形（正三角形正中央的輪軸和角落連成的三個小三角形不算；但輪軸若還連到三角形外的狀態，例如五個狀態兩兩相連排成格子時，照算） |
| `floating` | 和其他狀態都不在同一排或同一欄的狀態 |
| `long` | 比最短的線長 1.5 倍以上的線，超出多少 |
| `leftOfStart` | 在重設狀態左邊的狀態（閱讀應從左邊的重設狀態開始） |
| `aspect` | 形狀偏離寬高比 1.6（略寬於高，像螢幕）多少 |
| `labelOnEdges` | 標籤壓在其他線上 |
| `backward` | 逆著主流程（左到右或上到下）的線 |
| `asymmetry` | 不對稱的程度 |
| `slanted` | 斜線 |
| `length` | 線的總長 |
| `area` | 面積 |

## 用「選一個」調整權重

權重不是憑感覺定的：把同一台狀態機的兩種排法並排給人看，請他選比較好的，再調整權重讓分數和他的選擇一致。目前的權重和 23 組選擇全部一致。

這些選擇存在 `packages/core/test/layout/fixtures/preferences.json`。`tidy.test.ts` 裡有一個測試會逐組檢查「被選中的排法分數比較低」，所以以後改評分時，只要和任何一組選擇衝突，測試就會失敗。

再做一輪：

1. 產生比較頁：
   ```sh
   pnpm taste-test                       # 或 node tools/layout-taste-test/make-pairs.ts <輸出資料夾>
   ```
   會在 `tools/layout-taste-test/out/` 產生 `index.html`（比較頁）和 `pairs.json`（每組的兩種排法）。要比較的狀態機在 `tools/layout-taste-test/machines.ts`，可以自行加入。
2. 用瀏覽器開啟 `index.html`，每組選 A、B 或「差不多」，最後按「複製選擇（JSON）」，存成 `picks.json`。
3. 把選擇加進測試資料，並看目前的分數和幾組一致：
   ```sh
   node tools/layout-taste-test/apply-picks.ts tools/layout-taste-test/out/pairs.json picks.json 2026-11-01
   ```
4. 若有不一致的組，調整 `layout-score.ts` 的權重或加新的評分項目，直到 `pnpm test` 全部通過。

`layoutCandidates(d)`（`@fsm/core`）會回傳某張圖所有試過的排法和各自的分數，可以用來檢查或做自己的比較。
